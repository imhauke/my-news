Arquitectura de punta a punta

Todo corre en un VPS con Docker Compose salvo Gemini y las fuentes. Los puntos que circulan son datos: verdes los de ingesta, morados las llamadas a la IA y azules las peticiones de un lector.

ingesta y escriturallamadas a Geminipetición de un lectorBorde discontinuo: servicio externo

Worker

Cada 5 minutos descarga las tres fuentes en paralelo, deduplica, lee el artículo original para darle contexto a Gemini, enriquece lo nuevo (titular traducido, descripción, temas e importancia de 1 a 100) y rehace los resúmenes del día si toca. Una vez al día borra el historial ligado a un lector con más de un año.

API

FastAPI asíncrona. Sirve los feeds, el árbol de comentarios de HN (descargado y traducido bajo demanda), los resúmenes, las métricas y el chat sobre cada noticia en streaming. Registra votos y eventos en una sesión anónima solo si el lector lo acepta.

Frontend

React + TypeScript. Bilingüe, modo claro y oscuro, actualización cada minuto, animaciones con Motion y estado del lector (leídas, votos, consentimiento) en localStorage. Un panel flotante muestra los comentarios de HN o el chat de una noticia.

Preguntar

Un chat sobre cada noticia. Gemini responde en streaming a partir de la noticia (titular, descripción, inicio del artículo y comentarios de HN) y avisa cuando añade contexto general. Nada se guarda en el servidor.

Consentimiento

Sin aceptar no hay cookie: clics e impresiones se cuentan de forma anónima y los votos se quedan en el navegador. Al aceptar se crea una sesión anónima; retirarlo borra todo lo asociado y el historial caduca al año.

Dos Caddy

El edge es el único con puertos públicos y gestiona HTTPS para todos los dominios del servidor. El de MyNews solo habla HTTP dentro de Docker: sirve el frontend y reenvía /api.

Una restricción única en (source, external_id) convierte cada inserción en «insertar o actualizar»: la ingesta puede repetirse cada 5 minutos sin duplicar.

-- backend/app/api/routes.py
WITH RECURSIVE tree AS (
    SELECT id, author, text, text_es, created_at, depth, ARRAY[sibling_rank] AS path
    FROM hn_comments WHERE story_id = :story AND parent_id = :story AND NOT deleted
    UNION ALL
    SELECT c.id, c.author, c.text, c.text_es, c.created_at, c.depth, t.path || c.sibling_rank
    FROM hn_comments c JOIN tree t ON c.parent_id = t.id WHERE NOT c.deleted
)
SELECT id, author, text, text_es, created_at, depth FROM tree ORDER BY path

Los comentarios se guardan planos y la consulta recursiva los devuelve en orden de lectura; el frontend reconstruye el árbol con una pila.

Los tres resúmenes solo se rehacen si cambian las noticias principales (y han pasado 30 min) o cada 3 horas.

# backend/app/ranking.py — Gemini's importance plus what the server measures itself
def score(article: Article, now: datetime, coverage: int = 0) -> float:
    base = article.global_score or 0.0                     # importance 1-100 from stage 0, as 0-1
    base += COVERAGE_BONUS * min(coverage, MAX_COVERAGE)   # other outlets reporting the story
    if article.hn_points:
        base += HN_BONUS * min(article.hn_points / HN_FULL_POINTS, 1)
    age_hours = max((now - article.published_at).total_seconds() / 3600, 0)
    return base * math.pow(0.5, age_hours / HALF_LIFE_HOURS)   # halves every 18 h

Gemini puntúa con una rúbrica para un líder tecnológico (tecnología, seguridad y geopolítica que mueve mercados) y anclas de 1 a 100. Si cambia la rúbrica se sube SCORE_VERSION y el worker vuelve a puntuar las últimas 48 h.

# backend/app/chat.py — server-sent events, Flash-Lite first, Flash as the backup
async def answer(ai: AIClient, system: str, body: ChatIn) -> AsyncIterator[str]:
    turns = [(m.role, m.text) for m in body.messages]     # the browser keeps the conversation
    sent = False
    for model in (cfg.gemini_model_lite, cfg.gemini_model_flash):
        try:
            async for chunk in ai.stream_chat(turns, model=model, task=TASK, system=system, ...):
                sent = True
                yield _event("delta", {"text": chunk})
            yield _event("done", {"model": model})
            return
        except (AIError, QuotaExhausted):
            if sent:                                       # text already on screen: no restart
                break
    yield _event("error", {"code": "unavailable"})

Lite empieza a responder en menos de un segundo. El servidor no guarda conversaciones y limita a 20 preguntas por hora por visitante y 400 al día en total, con la IP real que le pasa Caddy.

CI/CD

Un push a main pasa por el CI y, si sale en verde, se publica y se despliega sin intervención.

CI: .github/workflows/ci.yml

  1. Backend: lint con ruff, tests con PostgreSQL + pgvector reales como servicio, y las migraciones aplicadas desde cero con alembic check para detectar deriva entre modelos y esquema.
  2. Frontend: npm ci, tipos con tsc, tests con Vitest y build de producción.
  3. Imágenes: construye las dos imágenes Docker con caché de GitHub para asegurar que el despliegue podrá hacerse.
  4. Eficiencia: permisos de solo lectura, cancela ejecuciones obsoletas de la misma rama y no se ejecuta si solo cambian documentos.

CD: .github/workflows/deploy.yml

# Only a green CI run from a push to main in this repository
if: >-
  github.event_name == 'workflow_dispatch' || (
    github.event.workflow_run.conclusion == 'success' &&
    github.event.workflow_run.event == 'push' &&
    github.event.workflow_run.head_branch == 'main' &&
    github.event.workflow_run.head_repository.full_name == github.repository
  )
# On the server: GHCR credentials only for the pull
echo "$REGISTRY_TOKEN" | ssh -i ~/.ssh/id_deploy "$TARGET" \
  "docker login ghcr.io -u $ACTOR --password-stdin && \
   cd $DEPLOY_PATH && export IMAGE_TAG=$TAG && \
   docker compose -f infra/docker-compose.prod.yml pull api worker web; \
   docker logout ghcr.io; \
   docker compose -f infra/docker-compose.prod.yml up -d --no-build"
Por qué esas cuatro condiciones. workflow_run se ejecuta con los secretos del repositorio incluso cuando el CI lo disparó una pull request de un fork, cuya rama puede llamarse main. Exigir event == 'push' y que el repositorio de origen sea este impide desplegar código ajeno.

Secretos y acceso

Clave SSH exclusiva de despliegue y huella del servidor en el environment production; el token de GHCR caduca al acabar el job.

Vuelta atrás

«Run workflow» con el SHA anterior: las imágenes están etiquetadas por commit.

Repositorio protegido

Sin force-push ni borrado en main, escaneo de secretos con bloqueo en el push y aprobación obligatoria para workflows de externos.

Caddy en un VPS compartido

El servidor ya alojaba otros proyectos y uno de ellos tenía su propio Caddy ocupando los puertos 80 y 443. MyNews no podía levantar otro.

# ~/edge/Caddyfile — one block per site
otro-proyecto.example, www.otro-proyecto.example {
	reverse_proxy otro-proyecto-web:80
}

news.janguzman.com {
	header Strict-Transport-Security "max-age=31536000"
	reverse_proxy mynews-web:80 {
		lb_try_duration 8s
	}
}
# infra/docker-compose.prod.yml — MyNews publishes no ports
web:
  image: ghcr.io/imhauke/my-news-frontend:${IMAGE_TAG:-latest}
  networks:
    default:
    edge:
      aliases: [mynews-web]

networks:
  edge:
    external: true
  1. Proxy común: un Caddy nuevo en su propia carpeta, dueño de los puertos públicos y de HTTPS para todos los dominios.
  2. Certificados: se copiaron los existentes al volumen del edge, así que no hubo que volver a emitirlos.
  3. Proyecto previo: su Caddy pasó a HTTP interno, con las mismas cabeceras de seguridad y rutas, y con trusted_proxies para seguir viendo la IP real del visitante. Se comprobó que una IP falsificada se ignora.
  4. Corte: unos 3 segundos sin servicio, con vuelta atrás automática preparada si la web no respondía.
  5. MyNews: se une a la red edge con el alias mynews-web; añadir otro proyecto es un bloque más en el Caddyfile del edge.

Lo que falta

Embeddings y búsqueda semántica

Calcular el vector de cada noticia con Gemini Embedding; con ellos la búsqueda por significado sale casi gratis.

Feed «Para ti»

Vectores de interés por lector, candidatos, puntuación con pgvector, re-ranking con Gemini con motivo, diversidad y exploración. Las señales ya se recogen.

Evals y experimentos

Set etiquetado a mano, métricas de ranking en el CI y A/B o interleaving entre variantes.

Agentes

El briefing con herramientas y trazas, y el servidor MCP para consultar las noticias desde Claude.
